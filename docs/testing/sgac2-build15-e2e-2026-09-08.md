The resident profile `TEST RESIDENT SEPT` and visitor profile `TEST VISITOR SEPT` were
generated from deterministic synthetic fixtures. Build 15 requires country/region code,
mobile number and email in the contact section. This differs from the build 13 walkthrough
notes that described email-only contact pages.

identity, date of birth and email through to review.

## Automation findings

The previously saved whole-Android Robot run remains at
[`Output/sgac2-build15-2026-09-08/`](../../Output/sgac2-build15-2026-09-08/): one test passed
and 23 failed. Live testing confirmed that most failures describe obsolete SGAC1 assumptions,
not the reachability of the build 15 flows:

- old tutorial and SGAC landing controls are referenced by profile/submission suites;
- the cargo suite expects the removed SGAC1 plus-button flow;
- the QR `NO, THANKS` control exists live, while the Robot variable reference fails;
- e-Service expected counts/text do not match the current raw-key content;
- local `sgac_epass` cases enter Device Farm setup.

Appium `send_keys` committed only the first character in masked date controls and sometimes
cleared protected identity inputs. Native Android keyboard events were used for those synthetic
fields. UiAutomator2 instrumentation also stopped twice and was recovered with new no-reset
sessions. These are harness/environment limitations; they are separated from application
findings in the results above.

The live build 15 contact screen also verified and added four missing foreigner locators in
`Data/sgac2/android/sgac/foreigner/for_profile_form.yaml`: country/region code input and label,
and mobile-number input and label. Each XPath resolves exactly once in the captured XML.

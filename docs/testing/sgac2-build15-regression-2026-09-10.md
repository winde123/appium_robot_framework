## Deltas vs the 2026-09-08 baseline

**Staging content fixes observed (previous defects no longer reproduce):**

- The garbled `X country**` health question is replaced in BOTH flows by a properly worded
  “Have you visited any of the listed countries^ in Africa or Latin America…” question with
  a live CDA yellow-fever link (`017`, `053`).
- The resident form no longer shows repeated health questions — two distinct questions,
  each rendered once (`017`–`019`).
- The visitor health section no longer contains `Dummy Question 1` (`052`–`053`).

**Defects still present:**

- The shared residence picker still lists the literal
  `ALBANIA<h1>test</h1>, OTHERS IN ALBANIA<h1>test</h1>, …` option (`033`).
- Valid native profile-form fields still display the cosmetic `Required` helper text
  (`006`–`007`), as in builds 13 and 15 baseline.

**New observation:**

- A Google Password Manager “Save password?” system dialog interrupted the visitor flow
  between web-form steps 1 and 2 (`056`), treating the email field as a credential. It was
  dismissed with *Not now*. This is an automation hazard for scripted runs (system dialog
  outside the app). **Mitigated 2026-09-10:** the GMS autofill and credential services were
  disabled on the Pixel_7_Pro AVD (`adb shell settings put secure autofill_service null`
  and `… put secure credential_service null`); the setting persists in the AVD data image.
  To revert: `adb shell settings put secure autofill_service
  com.google.android.gms/.autofill.service.AutofillService` and `… put secure
  credential_service com.google.android.gms/com.google.android.gms.auth.api.credentials.credman.service.PasswordAndPasskeyService`.

- Profiles from earlier sessions (`WALKTHROUGH QR RESIDENT`, `QR VISITOR SEPT`) were still
  present in both dashboards, and both new profiles persisted across in-app navigation.
  App-restart persistence was not re-tested this run.

## Harness findings

- **Protected identity inputs clear on modal/focus changes:** plain `setValue` into
  NRIC and Passport Number committed, then silently cleared after interacting with the
  Nationality modal (`006` shows both empty). Reliable method: tap the field, then type
  via W3C Actions key events into the focused element. This reproduces the baseline’s
  “protected identity inputs” note and should inform the T33 keyword implementation.
- **Masked date inputs took full strings this run** — the baseline’s first-character-only
  `send_keys` issue did not reproduce via `setValue` (DOB and expiry committed fully).
- **Webview radio buttons need coordinate taps:** accessibility-layer taps on the YES/NO
  label nodes often do not trigger the React handler (resident Q2 required a retap,
  `020`–`022`); tapping the `android.widget.RadioButton` node center always worked. The
  accessibility tree also does not expose `checked` state for these webview radios —
  verify selection from screenshots or the re-rendered validation state.
- **Webview combo options are invisible to the accessibility tree** (embarkation/purpose
  dropdowns): options render in screenshots but not in page source; select them by
  screenshot-derived coordinates.
- Two adb builds are installed (SDK 36.0.0 at `~/Library/Android/sdk/platform-tools`,
  Homebrew 37.0.1) and fight over the adb server on port 5037; use the SDK adb that
  Appium (via `ANDROID_HOME`) uses.
